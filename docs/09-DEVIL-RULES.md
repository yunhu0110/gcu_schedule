# 데블스 플랜 이벤트 운영 규칙 및 기능 명세

> 최종 업데이트: 2026-11-10

## 구현 현황 (2026-11-10)

- **백엔드**: `supabase/migrations/0018_devil.sql` — 테이블 7개 + RLS + RPC 3개 + 출연자 16명 시드.
  스포일러 차단은 **RLS로 서버에서 강제**(CSS 숨김 아님, §12):
  - `devil_eliminations` SELECT 정책 = `episode <= devil_watch_through(uid)` → 미시청 회차 행은 응답에 아예 없음.
  - `devil_final` SELECT 정책 = `devil_can_see_final(uid)`(14화 완료/동의/관리자).
- **API**: `src/api/devil.ts`. 저장은 트랜잭션 RPC(`devil_save_watch`·`devil_set_picks`·`devil_trade`).
- **화면**: 8개 기능 + 트레이드 + 탈락자 등록 전부 실제 데이터 연결.
- **적용한 기본값(§14 미확정분 중 코드가 필요로 한 것)**:
  - 예측 성공 기준 = 내 픽 2명 중 최종 우승자 포함 시 성공(winner.tsx).
  - 트레이드 기간·횟수 제한 없음(미설정). 탈락한 내 픽 교체 = 허용(out 제약 없음, in 만 탈락 불가).
  - 벌칙 발동 기준/내용/시점 = 여전히 미확정(penalty 화면에 명시).
- **운영 데이터 입력**: 탈락자는 앱 '탈락자 등록'(먼저 본 사람 누구나). 최종 우승자는 관리자가 `devil_final` 갱신(앱 UI 미제공 — 필요 시 추가).

## 1. 이벤트 기본 규칙

1. 데블스 플랜은 총 **14화**로 진행한다.
2. 이벤트 참여자는 총 **6명**이다.
3. 전체 출연자는 **16명**이다.
4. 참여자는 출연자 중 최종 우승할 것으로 예상하는 **2명**을 선택한다.
5. 1인당 2명씩 → 전체 12명이 참여자에게 배정된다.
6. 선택받지 못한 나머지 **4명은 FA(Free Agent) 시장**에 등록된다.
7. 각 출연자는 한 명의 참여자에게만 배정된다.
8. 참여자는 자신의 예측 출연자 2명을 관리하고, 실제 방송 결과에 따라 생존/탈락 여부를 확인할 수 있다.

## 2. 나의 예측 규칙

1. 참여자는 전체 출연자 중 2명을 선택한다.
2. 선택한 출연자 2명은 나의 예측 페이지에 저장한다.
3. 다른 참여자가 선택한 출연자 2명도 확인할 수 있다.
4. 선택한 출연자의 생존/탈락 여부는 **현재 로그인한 사용자의 시청 완료 범위까지만** 확인할 수 있다.
5. 최종 예측 성공/실패 여부는 **최종 결과 공개 조건을 충족한 경우에만** 확인할 수 있다.
6. 탈락 처리된 출연자는 새로운 예측 대상으로 선택할 수 없다.

## 3. FA 시장 및 트레이드 규칙

야구의 FA/트레이드 개념 적용.

### 3-1. FA 시장 구성

- 선택받지 못한 4명이 FA 등록
- FA 시장에는 현재 누구에게도 배정되지 않은 출연자만 표시
- 공식 탈락 출연자는 FA에서 제외
- 중복 영입 불가

### 3-2. 트레이드

나의 예측 페이지에 **트레이드 버튼**을 추가한다. 버튼 → 별도 트레이드 페이지로 이동.

트레이드 페이지 기능:
1. 내가 현재 선택한 출연자 2명 표시
2. 현재 FA 시장 출연자 목록 표시
3. 교체할 내 출연자 선택
4. 새로 영입할 FA 출연자 선택
5. 교체 전후 정보 확인
6. 트레이드 최종 확인
7. 완료 후 나의 픽·FA 시장 자동 갱신

### 3-3. 트레이드 예시

- A가 자신의 출연자 1을 FA의 출연자 13으로 교체하면:
  - A 새 픽: 출연자 13, 2
  - FA 시장: 출연자 1, 14, 15, 16

### 3-4. 트레이드 제한

1. FA 시장 출연자만 영입 가능
2. 이미 타 참여자가 선택한 출연자 영입 불가
3. 공식 탈락 출연자 신규 영입 불가
4. 트레이드 완료 전 확인 팝업 표시
5. 완료 후 픽·FA 목록 동시 갱신
6. 중복 배정 불가
7. 동시 영입 시 서버에서 트랜잭션으로 중복 방지
8. 트레이드 이력 별도 저장

## 4. 회차 시청 관리 규칙

1~14화 사용자가 직접 시청 완료 여부를 관리.

### 4-1. 시청 완료 등록 방식 (핵심)

> **체크박스 선택만으로는 저장되지 않는다. 반드시 '시청 완료 등록하기' 버튼을 눌러야 저장된다.**

1. 시청 완료한 회차의 체크박스 선택 → **임시 변경 상태**
2. '시청 완료 등록하기' 버튼 클릭
3. 선택한 회차 시청 상태를 서버에 저장
4. 저장 완료 후 연속 시청 완료 범위 재계산
5. 새롭게 접근 가능한 회차에만 결과 조회 권한 부여

### 4-2. 시청 기록 관리

1. 사용자 계정별로 독립 저장
2. A가 1화 시청 완료해도 B의 1화는 미시청 유지
3. 저장 버튼 전에는 기존 기록 변경 없음
4. 페이지 이탈 시 임시 변경 사항 버려짐
5. 기존 완료 회차 체크 해제 후 등록 → 해당 기록 취소
6. 시청 기록 변경 시 결과 조회 권한 재계산

## 5. 연속 시청 범위 규칙

> 결과 공개 범위 = **1화부터 연속으로 시청 완료한 가장 높은 회차**

| 상태 | 확인 가능 범위 |
|---|---|
| 1~3화 시청 완료 | 3화까지 |
| 1~5화 시청 완료 | 5화까지 |
| 1~5화 완료, 6화 미시청 | 5화까지 |
| 1화 미시청, 2화 완료 | 0화 (없음) |
| 1~3화 완료, 4화 미시청, 5화 완료 | 3화까지 |

중간 회차를 건너뛰어 미래 결과를 확인하는 것은 불가능해야 한다.

## 6. 스포일러 결과 확인 규칙

> **회차 시청 관리 페이지와 스포일러 결과 확인 페이지는 반드시 독립 구성**

### 6-1. 회차 시청 관리 페이지에서 절대 표시 금지

- 회차별 탈락자 이름·프로필
- 생존자 목록
- 출연자별 탈락 여부
- 나의/타인의 예측 성공·실패
- 최종 우승자

회차 카드에는 **시청 여부만** 표시한다.

### 6-2. 스포일러 결과 확인 페이지

1. 1~14화 회차 선택
2. 연속 시청 완료 범위 내 회차만 결과 확인 가능
3. 미시청 회차는 잠금 상태 표시
4. 잠긴 회차에는 탈락자·생존자 정보 표시 금지
5. 결과 확인 버튼 → 스포일러 경고 팝업
6. 사용자 명시 확인 후에만 공개

**경고 팝업 예시**
> "7화 결과를 확인하시겠습니까?  
> 결과에는 탈락자 및 생존자 정보가 포함되어 있습니다."

### 6-3. 회차별 결과 정보

- 해당 회차 탈락자
- 해당 회차까지 생존 출연자
- 내가 예측한 출연자 2명의 생존 여부

일반 회차 결과 조회 중 **최종 우승자 정보가 노출되면 안 된다.**

## 7. 나의 예측 생존 현황 페이지

내가 선택한 출연자 2명의 현재 상태 확인 페이지.

표시 정보:
- 출연자 프로필 이미지·이름
- 생존 또는 탈락 상태
- 탈락한 경우 탈락 회차
- 현재 확인 가능한 기준 회차

규칙:
1. 연속 시청 완료 범위까지만 반영
2. 시청하지 않은 회차 이후 탈락 여부 표시 금지
3. 현재 생존 중인 출연자는 반드시 기준 회차 명시
4. "최종 생존자" 또는 "우승자"로 표현 금지
5. 미확인 정보는 "시청 후 확인 가능" 또는 "미확인"으로 표시
6. 최종 예측 성공·실패는 최종 결과 공개 조건 충족 후에만 표시

## 8. 전체 생존자 확인 페이지

사용자가 시청 완료한 범위까지의 전체 생존자 목록 페이지.

규칙:
1. 연속 시청 완료 범위 기준으로 생존자 계산
2. 5화까지 시청했다면 5화 종료 기준 생존자만 표시
3. 이후 회차 탈락 정보 포함 금지
4. 최종 우승자와 혼동되지 않도록 현재 생존 상태만 표시

## 9. 참여자 예측 현황 페이지

다른 참여자들이 선택한 출연자 2명 확인 페이지.

규칙:
1. 다른 참여자의 예측 출연자 2명 확인 가능
2. 출연자 생존·탈락 여부는 **현재 로그인한 사용자의 시청 범위** 기준으로 표시
3. 타 참여자가 14화까지 시청했더라도 나에게는 나의 시청 범위까지만 공개
4. 타 참여자의 시청 기록이 나의 결과 공개 범위에 영향을 주지 않음
5. 타 참여자의 예측 성공·실패는 최종 결과 공개 전까지 표시 금지

## 10. 최종 결과 공개 규칙

최종 우승자 및 최종 예측 성공 여부는 일반 회차 결과와 별도 보호.

**공개 조건** (둘 중 하나 충족):
1. 1~14화 전체 시청 완료
2. 별도의 최종 스포일러 확인 절차에 명시적으로 동의

최종 결과 페이지 정보:
- 최종 우승자
- 나의 예측 성공 여부
- 다른 참여자의 예측 성공 여부
- 이벤트 최종 결과
- 벌칙 적용 결과

규칙:
1. 일반 회차 결과 과정에서 최종 우승자 노출 금지
2. 최종 결과 페이지 진입 시 스포일러 경고 표시
3. 최종 스포일러 동의는 회차별 접근 권한과 분리
4. 최종 결과 공개 여부는 현재 로그인한 사용자 권한 기준

## 11. 벌칙 안내 규칙

- **조건**: 자신이 선택한 출연자 2명이 **모두 조기 탈락**하면 벌칙 대상
- 벌칙 발동 회차·내용·적용 시점은 **최종 확정 필요** (미확정)
- 벌칙 대상 여부는 실제 탈락 결과 기준으로 판단
- 미시청 결과가 먼저 노출되지 않도록 한다

## 12. 데이터 보안 및 접근 제어

스포일러 방지는 **서버의 데이터 접근 제어 단계**에서 구현.

1. 회차 시청 관리 API: 탈락자·생존자 결과 데이터 반환 금지
2. 일반 사용자에게 전체 회차 탈락자 목록 미리 전달 금지
3. 결과 조회 API: 서버에서 사용자의 시청 상태 검증
4. 연속 시청 완료 조건 서버 검증 필수
5. 미시청 회차 결과는 API 응답에도 포함 금지
6. **CSS로 결과를 숨기는 방식 사용 금지**
7. 개발자 도구·네트워크 응답으로 미래 결과 확인 불가해야 함
8. 시청 완료 취소 시 이후 회차 접근 권한 재검증
9. 관리자 계정: 관리 목적 전체 조회 예외 권한
10. 타 사용자 시청 상태 임의 변경 불가
11. 사용자 본인의 인증 정보 + 서버 시청 기록 기준으로 접근 권한 판단
12. FA 트레이드 동시 진행 시 서버 트랜잭션으로 중복 배정 방지
13. 결과 데이터와 일반 데이터는 저장·조회 권한 분리

## 최종 핵심 원칙

1. **시청 기록 저장**: 체크박스가 아니라 '시청 완료 등록하기' 버튼을 눌렀을 때 저장
2. **결과 공개 범위**: 현재 로그인한 사용자의 연속 시청 완료 회차 기준
3. **FA/트레이드**: 6명 참여자·16명 출연자 통합 관리, 중복 배정 없이 실시간 갱신
